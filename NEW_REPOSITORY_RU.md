# NoteSound — установка в НОВЫЙ репозиторий GitHub

Этот архив содержит весь проект (не только патч): исходные файлы, public/assets, сервер Render, тесты и GitHub Actions. Распакуйте ZIP и загрузите **содержимое** распакованной папки в корень нового репозитория. Сам ZIP загружать в репозиторий не нужно.

## Загрузка через GitHub Desktop (Windows)

1. Создайте новый репозиторий на github.com. Удобное имя — `NoteSound`; если имя другое, workflow сам вычисляет префикс сайта по имени репозитория. Не выбирайте **Add a README**, чтобы репозиторий был пустым.
2. В GitHub Desktop: File → Clone repository → URL. Вставьте адрес нового репозитория и выберите **Clone**. Если GitHub Desktop предлагает открыть/создать репозиторий, убедитесь, что работаете именно в **новом**, а не в прежнем NoteSound.
3. В GitHub Desktop нажмите Repository → Show in Explorer. Откроется папка нового репозитория.
4. Распакуйте ZIP отдельно. Выделите всё содержимое архива (включая `.github` и другие скрытые файлы), скопируйте в папку нового репозитория. Не копируйте внутрь дополнительную папку.
5. Вернитесь в GitHub Desktop, убедитесь, что видите много новых файлов. Summary: `Initial NoteSound modernization`. Нажмите **Commit to main**, затем **Push origin / Publish branch**.
6. На GitHub: Settings → Pages → Build and deployment → Source: **GitHub Actions**. В Actions откройте **Build and deploy NoteSound** и посмотрите результат. GitHub Actions запустится при push в `main`; при необходимости используйте Run workflow.
7. Сайт обычно доступен по адресу `https://ВАШ_ЛОГИН.github.io/ИМЯ_НОВОГО_РЕПОЗИТОРИЯ/` после успешного deploy (для обычного репозитория, не персонального `username.github.io`).

## Render и работа внешнего поиска

- В новом репозитории есть `render.yaml`, `server/` и `server/.env.example` — они нужны для настройки отдельного backend Render. GitHub Pages запускает **только интерфейс**, Node.js-сервер на GitHub Pages не работает.
- На Render выберите New → Blueprint/или Web Service, укажите новый GitHub-репозиторий и проверьте параметры и переменные окружения. Установите `APP_ORIGINS=https://ВАШ_ЛОГИН.github.io` и другие необходимые настройки. **Не публикуйте токены в коде или VITE_* переменных**.
- На GitHub: Settings → Secrets and variables → Actions → Variables добавьте `VITE_DISCOVERY_API_URL` с HTTPS-адресом нового сервера Render, например `https://ВАШ-СЕРВИС.onrender.com`; при необходимости `VITE_MUSIC_API_URL`. Затем повторите workflow.
- Другой вариант: после сборки скорректировать публичный `config.js` (см. `public/config.js`) и опубликовать снова. Не храните приватные ключи в config.js.
- Условия SoundCloud могут требовать отдельного одобрения; без него автоматический каталог SoundCloud не включается. Зелёный GitHub Actions не означает, что внешние сервисы или фоновое воспроизведение Telegram протестированы.
