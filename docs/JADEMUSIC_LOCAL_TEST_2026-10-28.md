# Локальная проверка JadeMusic — 28 октября 2026

Источник: https://github.com/nshib00/jademusic-api

Тест работает отдельно от NoteSound: http://127.0.0.1:8001/

Для запуска использованы отдельное окружение Python в `.qa/jademusic-env`, SQLite вместо PostgreSQL и совместимые версии зависимостей. Простая стартовая страница добавлена для проверки API; она не является оригинальным интерфейсом JadeMusic. Запрос определения источника отложен до поиска. Доступны только маршруты чтения; скачивание и регистрация не подключены. Папка загрузок перенесена внутрь тестового окружения.

Проверено: Django check без ошибок; маршрут статуса возвращает HTTP 200; поиск MACAN возвращает HTTP 502 на стадии source_discovery — внешний сайт определения источника не удалось получить. Это не означает отсутствие песни. Маршрут скачивания возвращает HTTP 404. Музыка не скачивалась.

Перезапуск из папки MusicTG в PowerShell:

```powershell
& '.qa/jademusic-env/Scripts/python.exe' .qa/jademusic-run/launch.py runserver 127.0.0.1:8001 --noreload
```

Сервер доступен только на этом компьютере. Публикация и подключение к NoteSound не выполнялись. Тест не подтверждает работоспособность музыкального каталога JadeMusic.

## Уточнение причины ошибки и исправление страницы

Вечером 28 октября проверен адрес `gde-hitmo.org`, зашитый в исходном `audioparser/hitmo/url.py`. Системный DNS вернул `socket.gaierror 11001`; контрольные `github.com` и `example.com` разрешаются нормально. HTTP-ответ от сайта не получен. Это локальное наблюдение, а не доказательство недоступности домена во всех сетях и не HTTP 403.

В оболочке теперь записывается этап ошибки до сетевого запроса. При открытии поиска в браузере отображается русское объяснение; программные запросы сохраняют JSON с читаемым UTF-8. Ошибки соединения не выдаются за отсутствие песни. Успешный адрес источника сохраняется только после настройки парсера; состояние HTTP сбрасывается перед новым запросом. Пять автоматических проверок диагностики и Django check прошли.

## Ограничение зависающих запросов

Системное определение адреса может ждать дольше тайм-аута HTTP. Поэтому вся проверка источника и исходный парсер теперь выполняются в отдельном процессе, который завершается при превышении 15 секунд. Блокировка освобождается после остановки процесса. Повторному запросу во время проверки возвращается HTTP 202 с русским объяснением и Retry-After; служебная строка `Another source test is running` удалена. Ошибка определения источника хранится 60 секунд, чтобы частые клики не повторяли сетевой запрос.

Девять автоматических проверок и Django check прошли. Реальная одновременная проверка: первый запрос завершился HTTP 502 через 12,39 секунды (DNS источника); второй получил страницу ожидания HTTP 202 за 0,02 секунды. После завершения `busy=false`; повторный запрос получил сохранённое объяснение без нового ожидания. Подключение музыкального каталога этим не исправлено.
