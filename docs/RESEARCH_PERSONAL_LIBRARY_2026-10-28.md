# Личная музыкальная библиотека для NoteSound: исследование 28 октября 2026

Проверены официальные документация и репозитории. Установок, регистрации, открытия портов, загрузки музыки, отправки сообщений и изменений приложения не выполнялось. Код NoteSound изучен только для оценки интеграции.

## Главный вывод

Для небольшого закрытого круга технически реалистичен бесплатный **Navidrome на имеющемся компьютере + NoteSound как клиент его API**. Это решает хранение, поиск и воспроизведение собственной коллекции. Ни Navidrome, ни Jellyfin, ни Nextcloud Music не предоставляют готовую библиотеку русских хитов и не находят автоматически «ДИНАСТИЮ» в интернете. Запись появится, когда доступный для соответствующего использования файл будет добавлен в коллекцию.

Самая небольшая доработка существующего проекта — серверная библиотека файлов с авторизацией и потоковым маршрутом в текущем Node API. Однако тогда NoteSound придётся самостоятельно реализовать функции, уже имеющиеся в Navidrome: сканирование папок, метаданные, обложки, пользователей и каталог. Для долговременной коллекции предпочтительнее готовый музыкальный сервер.

## Сравнение

| Вариант | Полные аудиофайлы | Готовый каталог хитов | Windows / сложность | Применимость |
|---|---|---|---|---|
| Текущий импорт NoteSound | Да, выбранные файлы хранятся локально в браузере | Нет | Уже реализовано | Самый быстрый личный режим, но общая библиотека между устройствами не появляется |
| Navidrome | Да, из своей папки; поддерживает поток и транскодирование | Нет | Официальный Windows MSI; музыкальная специализация | Лучший основной кандидат для частной коллекции |
| Jellyfin | Да, из собственных медиатек | Нет | Официальный Windows installer; больше функций и настроек | Хорошо, если нужен также домашний сервер видео или Jellyfin уже установлен |
| Nextcloud Music | Да, из файлов собственного Nextcloud; Ampache/Subsonic API | Нет | Требует Nextcloud, PHP и БД; официальный серверный стек ориентирован на Linux | Разумно при уже существующем Nextcloud, избыточно для одного NoteSound |
| Ampache | Собственная коллекция, OpenSubsonic/Subsonic интерфейс | Нет | PHP-сервер и его инфраструктура | Альтернатива уже настроенному серверу, отдельного преимущества перед Navidrome для этого проекта не установлено |
| Загрузка личного аудио боту | Бот может получить отправленный пользователем файл | Нет | Нужны backend, хранилище и обработчик сообщений | Удобный способ пополнения коллекции, не самостоятельный музыкальный источник |
| Собственная папка + текущий Node API | Да, после реализации файловой выдачи | Нет | Можно запускать на Windows; меньше отдельных программ | Быстрый ограниченный пилот, но больше собственного сопровождения |

## Navidrome

Официальная документация описывает браузерный доступ, несколько пользователей и библиотек, чтение тегов, обложки и потоковое воспроизведение. Windows MSI создаёт службу и предлагает базовые настройки. Доступный OpenSubsonic/Subsonic API содержит `search3`, `getSong`, `getCoverArt`, `stream`, очередь и избранное. Его можно адаптировать к существующему MusicProvider NoteSound. Сам вызов `stream` не учитывается Navidrome как прослушивание: клиент должен отдельно вызывать `scrobble`; это позволяет не создавать фиктивную историю при предварительной буферизации.

Фактическая установка, CORS и воспроизведение в Telegram в этом исследовании не проверялись. Официальная совместимость API — основа для интеграции, а не доказательство, что существующий NoteSound подключится без изменений.

Источники: [обзор](https://www.navidrome.org/docs/overview/), [Windows MSI](https://www.navidrome.org/docs/installation/windows/), [API](https://www.navidrome.org/docs/developers/subsonic-api/).

Для внешнего подключения Navidrome рекомендует reverse proxy и SSL. Серверу достаточно чтения папки музыки и записи в отдельную папку данных. Нельзя помещать административные логин/пароль в публичный JavaScript. Встроенные или проксируемые способы авторизации следует настроить явно и проверить доступ разных пользователей; факт входа в Telegram сам по себе не является входом в музыкальный сервер. [Рекомендации Navidrome](https://www.navidrome.org/docs/usage/admin/security/).

## Jellyfin и Nextcloud

Jellyfin имеет Windows installer и музыкальные библиотеки на базе собственных файлов/тегов. Доступ может ограничиваться пользователями, включая запрет удалённых соединений. Для интернета документация рекомендует HTTPS и описывает VPN/reverse proxy; прямое открытие порта не рекомендуется. Новый provider и авторизация NoteSound всё равно потребуются. [Windows](https://jellyfin.org/docs/general/installation/windows/), [музыка](https://jellyfin.org/docs/general/server/media/music/), [сеть и доступ](https://jellyfin.org/docs/general/post-install/networking/).

Важное изменение на 2026 год: актуальный **Nextcloud Music** находится в [nc-music/music](https://github.com/nc-music/music). Прежний `owncloud/music` перенаправляет на [nc-music/oc-music](https://github.com/nc-music/oc-music), который переведён в режим обслуживания для ownCloud. Текущий Nextcloud Music предоставляет внешним клиентам Ampache/Subsonic, использует собственные облачные аудиофайлы и специальные API-ключи вместо обычного пароля пользователя. Собственный внутренний REST API интерфейса может меняться; для NoteSound разумнее совместимый публичный протокол. Сервер Nextcloud добавляет PHP, БД и веб-сервер; в официальных требованиях перечислены Linux-системы, поэтому это не самый короткий путь на текущем Windows-компьютере. [Карточка приложения](https://apps.nextcloud.com/apps/music), [серверные требования](https://docs.nextcloud.com/server/35/admin_manual/installation/system_requirements.html).

Ampache также имеет OpenSubsonic API, отдельные пользовательские API-ключи и настройки совместимости. Это подтверждённый протокол для собственных библиотек, но не внешний каталог русских релизов. [Документация Ampache](https://ampache.org/api/subsonic/).

## Telegram как вход для личных файлов

Возможна схема: пользователь отправляет боту **свой разрешённый аудиофайл**, backend проверяет отправителя, сохраняет файл и метаданные, затем библиотека сканируется и становится доступна нужным аккаунтам NoteSound. Личный файл не должен автоматически становиться общим для всех друзей: права доступа и круг использования задаются отдельно.

Обычный облачный Bot API позволяет получать файлы через `getFile` до 20 МБ. Для `sendAudio` указаны MP3/M4A и до 50 МБ при загрузке; при передаче Telegram HTTP URL действует отдельное ограничение 20 МБ. Локальный Bot API снимает предел скачивания и допускает загрузку до 2000 МБ, но требует ещё одного сервера. Для небольших MP3 такой дополнительный компонент обычно не нужен.

Ссылка скачивания `getFile` включает **BOT_TOKEN**. Её нельзя выдавать frontend как публичный аудиоисточник: файл нужно безопасно получить на backend, затем использовать собственную авторизованную выдачу. `file_id` — идентификатор файла конкретного бота, не универсальный URL аудио и не поиск по общей музыке Telegram. Нельзя обещать, что бот сможет искать все песни по чужим чатам.

Источники: [getFile](https://core.telegram.org/bots/api#getfile), [sendAudio](https://core.telegram.org/bots/api#sendaudio), [Local Bot API](https://core.telegram.org/bots/api#using-a-local-bot-api-server).

## Совместимость с текущим NoteSound

Изучены `src/adapters/music/index.ts`, `src/services/storage/db.ts`, `server/index.mjs`.

- Личный импорт сейчас — Blob в IndexedDB устройства; это не серверная синхронизация и не библиотека друзей.
- MusicProvider уже отделяет поиск/метаданные от разрешения аудио. Можно добавить `SubsonicProvider`, сохранив плеер, Smart Wave и очередь.
- Нынешний Node backend принимает статический реестр лицензированных записей и проверяет удалённый источник через HEAD; он **не имеет** загрузки файлов, потокового прокси, каталога личных библиотек и связанных разрешений пользователей.
- Проверка Telegram initData/сеанса уже есть, но нужен отдельный список допуска и сопоставление пользователей с библиотеками. Сейчас это не реализовано.
- Секрет Navidrome/Nextcloud остаётся на backend. Для проигрывания нужны серверная проверка доступа и короткоживущая ссылка либо строго ограниченный потоковый маршрут. Нельзя делать универсальный прокси произвольного URL.
- Для файла следует проверить HTTP Range/перемотку, правильный MIME, длительность, обложку и CORS. Для Wave Mix нужен фактический доступ Web Audio и разрешение на соответствующее использование записи. Режим `crossOrigin` управляет CORS-запросами медиа; наличие обычного звука не доказывает совместимость со сведением. [HTMLMediaElement.crossOrigin](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/crossOrigin).

Вывод о предпочтительности Navidrome — инженерная оценка текущего кода. Его готовый API уменьшает объём новой серверной логики, но ещё не проверен живым подключением к NoteSound.

## Бесплатность и постоянное хранение

На имеющемся компьютере можно обойтись без отдельной подписки на музыкальный сервер. Останутся включённый компьютер, дисковое место, электричество, интернет и обслуживание. Если он выключен, телефоны коллекцию с него не получат. Нулевую стоимость круглосуточного облака обещать нельзя.

Для масштаба: 1000 записей по 3 минуты при 320 кбит/с занимают приблизительно 7,2 ГБ без обложек и служебных данных. Пять одновременных потоков такого качества потребуют около 1,6 Мбит/с исходящего трафика до накладных расходов. Это расчёт, не измерение текущего соединения пользователя.

**Render Free не подходит как постоянная папка музыкальной коллекции.** Данные, записанные в его файловую систему, исчезают при перезапуске, повторной публикации и засыпании; постоянный диск на Free недоступен. Есть засыпание после 15 минут без запросов и лимиты использования. Это годится для диагностики и небольшого API без локального постоянного контента. [Render Free](https://render.com/docs/free).

## Фон и границы результата

Смена источника на свой сервер не подтверждает работу аудио после сворачивания Telegram на iPhone. Это отдельная задача жизненного цикла WebView/ОС, требующая проверки устройства. Системное воспроизведение сообщения `sendAudio` идёт уже в плеере Telegram; оно не означает, что Smart Wave и двухканальный Mix продолжат выполняться внутри закрытого Mini App. В документации Mini Apps описаны состояние активности и связанные события; гарантии непрерывного фонового аудио для нашего сценария не установлены. [Telegram Mini Apps](https://core.telegram.org/bots/webapps).

## Предлагаемый порядок пилота

1. Выбрать личную коллекцию разрешённых файлов и требуемый круг доступа. Это не заменяет поиск готового каталога хитов.
2. Если коллекции пока нет, не разворачивать сервер под обещание, что он сам наполнится.
3. При наличии коллекции проверить Navidrome локально на Windows на нескольких разрешённых записях.
4. Добавить provider и серверную привязку аккаунтов; подтвердить настоящий поток, перемотку, отказы авторизации и восстановление сеанса.
5. Затем проверить HTTPS/CORS и телефон; после обычного аудио — независимый Wave Mix.
6. Только после рабочего пилота решать удалённый доступ и постоянный хостинг. Сейчас установки и публикации не выполнялись.
