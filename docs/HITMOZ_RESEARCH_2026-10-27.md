# Проверка Hitmoz и источников «Династии»

Проверено 27 октября 2026 года. Цель — VILLIAN, madk1d — «ДИНАСТИЯ», полная запись примерно 2:30. Ниже исследованные кандидаты, а не заявление о проверке всех музыкальных сайтов в интернете. Коммерческие аудиофайлы в ходе исследования не скачивались.

## Hitmoz

- Веб-инструмент получил HTTP 403 для корневых страниц `ru.hitmoz.org` и `eu.hitmoz.com`.
- Дополнительные обычные HEAD-запросы с публичным `Origin: https://example.github.io`, без cookies и авторизации: `ru.hitmoz.org/` и `ru.hitmoz.org/robots.txt` — таймаут 10 секунд; `eu.hitmoz.com/` — HTTP 403, `text/html`, без `Access-Control-Allow-Origin`; `eu.hitmoz.com/robots.txt` — таймаут 10 секунд.
- Это результаты текущего соединения; они не доказывают глобальную недоступность сайта или состояние CORS для всех его адресов. Обход запрета, подмена cookies/авторизации и извлечение аудио за ограничением не выполнялись.
- Наличие искомой записи в Hitmoz и разрешение на использование его файлов сторонним приложением не подтверждены.

[Сторонний репозиторий](https://github.com/Shukurov777/hitmoz-parser) и его [актуальный parser.py](https://raw.githubusercontent.com/Shukurov777/hitmoz-parser/main/parser.py) действительно описывают техническую схему: серверный Python `requests`/BeautifulSoup получает HTML `eu.hitmoz.com/search?q=...`, извлекает ссылки `/get/music/*.mp3`, а PHP-обёртка предоставляет собственный JSON endpoint. Это не опубликованный API самого Hitmoz. README обозначает образовательное назначение и права владельцев контента. MIT-лицензия кода не лицензирует песни. GitHub Pages не выполняет Python/PHP, поэтому такой серверный парсер нельзя просто включить в статическое React-приложение.

## Musify: искомая песня найдена, разрешён iframe своего плеера

[Страница точной записи](https://musify.club/track/villian-madk1d-dinastiya-22487355) содержит имена VILLIAN/Madk1d и длительность 2:30. Обычный GET вернул HTTP 200. В ответе не обнаружены `X-Frame-Options` и `Content-Security-Policy`, запрещающие встраивание; это не заменяет проверку iframe в браузере.

[Условия самого Musify, пункт 5.1](https://musify.club/en/contacts/terms), прямо разрешают использование контента через плеер сайта на сторонних страницах посредством embed/iframe и временные технические копии в пределах функционала сервиса. [Правовая информация](https://musify.club/contacts/legal) описывает лицензионную модель сервиса. Эти условия не трактуются здесь как неограниченное разрешение NoteSound копировать и распространять MP3.

В публичном JavaScript найден внутренний `/api/track/{id}/stream-url`. Обычный GET `/api/track/22487355/stream-url` без cookies и авторизации вернул HTTP 200 с JSON-полями `url`, `title`, `cover`, `trackUrl`, но **без `Access-Control-Allow-Origin`** при внешнем Origin. Аудиоссылка не сохранялась и аудио не скачивалось. Браузерный React-клиент с GitHub Pages не может напрямую прочитать такой ответ через fetch.

В исследованном коде `main.CDlhgbgN.js` нет `postMessage` интерфейса управления iframe и отдельного документированного music-widget endpoint. Найден только внутренний `CompactPlayer`; `iframe`/`embed` в коде относятся к видеоклипам YouTube. В справке отдельный API управления внешним плеером не найден. Поэтому полноценную интеграцию play/pause/ended/queue через Musify пока нельзя обещать. Разрешённое встраивание страницы с собственным плеером — возможный отдельный режим с его собственными контролами и лимитами, требующий браузерной проверки. Лимиты/регистрация/Premium сервиса сохраняются.

## Практическое решение

Нужны либо публичный источник, допускающий сторонний потоковый плеер, либо официальный встраиваемый плеер. Из исследованных MP3-площадок Musify имеет явное разрешение на iframe, но не подтверждённый внешний API управления. Прямое скачивание коммерческой записи из Hitmoz не реализовано и не представляется как работающая функция. Официальные видеоплееры рассматриваются отдельно: они позволяют слушать полную песню внутри NoteSound без извлечения и повторного распространения MP3, сохраняя ограничения провайдера.

## Реализованный адаптер

`src/adapters/music/musify.ts` содержит семь проверенных metadata-записей, локальный поиск по названиям/исполнителям/алиасам `madkid`, и только ссылки на плеер сайта. `resolveStream` всегда возвращает `null`, `supportsDownload` — `false`. `checkAvailability` проверяет принадлежность ранее проверенному каталогу и точное совпадение разрешённого iframe URL, а не утверждает успешность текущего аудиозапуска. Изменения прав, гостевых лимитов и сетевые ошибки должен показывать настоящий плеер источника.

`findMusifyTrack` подбирает резервную страницу по нормализованным названию/исполнителю с проверкой длительности (разница не более 12 секунд). Поэтому оригинальные «Поезда» на Musify не подставляются автоматически вместо другой 149-секундной версии с Бастой. Тесты также проверяют, что ремикс не заменяется оригиналом и недоступная «Сансара» не попадает в каталог. Пять тестов адаптера проходят, scoped ESLint — без ошибок.
