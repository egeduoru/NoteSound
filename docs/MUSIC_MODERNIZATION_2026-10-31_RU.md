# NoteSound · модернизация музыкальной системы, 31.10.2026

**Статус:** существенная частичная реализация в исходном проекте, **не подтверждённый публичный релиз**. Внешний вид исходного NoteSound, основная маршрутизация, оригинальный Player, оформление, шрифты, основная библиотека и существующий Wave Mix оставлены; разрешённый официальный SoundCloud Widget при проигрывании добавляет отдельную обязательную атрибуцию и видимый iframe, поскольку скрывать его нельзя. Никакие записи в IndexedDB не стираются миграцией этого изменения. Для сертификации выпуска остаются полноценная сборка и реальные проверки на устройствах.

## 1. Что действительно сделано

* **Независимый серверный модуль** `server/music-intelligence.mjs`: запросы в MusicBrainz, экспериментальные рекомендации ListenBrainz и лицензируемый поиск SoundCloud отделены от существующих серверных адаптеров. Тайм-ауты, ограничение 1 запроса MusicBrainz за 1100 мс, кеш и coalescing повторных запросов; при сбое сторонней системы остальные части приложения не обязаны падать.
* **MusicBrainz**: серверный `/api/music/metadata?q=...` возвращает идентификатор MBID, название, исполнителя, приблизительную длительность и score, но **не выдаёт запись за воспроизводимую**.
* **ListenBrainz**: `/api/music/recommendations?username=...` выдаёт доступные публичные recording MBIDs; `/api/music/similar?q=исполнитель+песня` сопоставляет стартовую запись через MusicBrainz, затем запрашивает экспериментальную выдачу ListenBrainz Labs. `src/services/recommendation/listenbrainz.ts` использует эти предложения только как **строки поиска/метаданные**; найденное аудио дополнительно проходит фильтры соответствия и доступности существующих провайдеров. Без записей или доступного API очередь корректно заканчивается.
* **SoundCloud**: без согласия на использование API в качестве музыкального каталога интеграция выключена серверной переменной `SOUNDCLOUD_CATALOG_APPROVED=false`; **никакого бесплатного общедоступного поиска по всему SoundCloud не обещается**. При подтверждённом разрешении и серверных OAuth-ключах `/api/discovery/soundcloud/search?q=...` находит кандидатов через официальный API и проверяет их соответствие и oEmbed. Ремиксы/каверы, когда их не просили, отбрасываются по названиям; это **не доказывает подлинность загрузки или авторство**. Доступная ссылка запускается через официальный видимый SoundCloud Widget и его публичные Play/Pause/Seek/FINISH события, не через извлечение аудиопотока. Видимый iframe может занимать дополнительное место; невозможно одновременно сохранить 100% пикселей старого интерфейса и выполнять правила атрибуции SoundCloud при встраивании.
* **Оригинальный Playback Manager** использует третий, взаимоисключающий адаптер SoundCloud наряду с существующими источниками. Вся обычная навигация React остаётся прежней; SoundCloud iframe монтируется в общем Shell, не во вкладке поиска. Добавлены обработчики событий, тайм-ауты, отмена устаревших загрузок, смена громкости и отслеживание времени.
* **Контексты очередей**: `favorites`, `playlist`, `album`, `history`, `library` и `wave`. При запуске из избранного и плейлиста очередь берётся из соответствующей коллекции; начиная с выбранной записи порядок сохраняется. Shuffle перемешивает остальные элементы выбранной коллекции, Repeat all перезапускает набор, Repeat one повторяет текущую запись. Переключение вкладки не меняет контекст воспроизведения. `album` поддержан на уровне модели очереди, но в текущей сохранённой UI-структуре отдельного пользовательского альбомного представления **нет**.
* **Настройки источников** расширены внутри прежнего экрана: SoundCloud (выключен по умолчанию), публичный аудиокаталог, Deezer (фрагменты) и лицензированный каталог; отключение останавливает текущий трек этого источника, не удаляя метаданные, плейлисты, лайки. Переключатель автоматического подбора уже существовал и оставлен.
* **Сохранение**: текущие трек/позиция, контекст очереди, список коллекции, включённые источники записываются в существующее хранилище; не добавлены таблицы с непроверенными подписанными аудиоссылками. Существующая логика сохранения избранного, истории и плейлистов сохранена.
* **Wave Mix** не получает прав на обработку SoundCloud: внешние виджеты только для воспроизведения. Существующие совместимые источники продолжают использовать прежний Mix.

## 2. Ограничения и нереализованные обещания

1. **SoundCloud Search** недоступен без подходящего разрешения от SoundCloud и одобренных credentials. Widget API, oEmbed и наличие ссылки не предоставляют права на запуск агрегированного стриминга. Включение булевой переменной без прав — нарушение условий; не делать этого.
2. **Реальная доступность MACAN, ASPHALT 8, madk1d, «ДИНАСТИЯ», VILLIAN, русскоязычного рэпа** через SoundCloud, MusicBrainz и ListenBrainz **не подтверждена** из этой среды. Тесты используют фиксированные правдоподобные значения с *моками*, не результаты живого запроса. Нет измеренного процента покрытия русскоязычных песен; нельзя представлять его числом.
3. **Полноценная проверка Play/Pause/Seek, iPhone, Android, Telegram Mini App, заблокированного экрана, автоматического перехода, Media Session и React ErrorBoundary не запускалась**. События SoundCloud асинхронны и зависят от браузера, политики автозапуска и условий встраивания; следующий трек в заблокированном Telegram не гарантирован.
4. **Фоновая работа и экран блокировки:** оставлены Media Session handlers оригинального приложения, но их доступность определяется Telegram/WebView и ОС. Поведение на физических устройствах пока неизвестно.
5. **Альбомы:** модель `album` есть, однако текущий архив не содержал активного UI открытия альбома как отдельной коллекции. Новую вкладку и новый дизайн не добавляли ради сохранения интерфейса.
6. **Полный пересчёт музыкального сходства** не реализован: ListenBrainz Labs возвращает экспериментальные похожие записи; MusicBrainz не предоставляет собственный сервис семантической похожести; результат может быть пустым или недоступным.
7. **Автоматическое подтверждение оригинальной коммерческой записи** по совпадению метаданных невозможно: на SoundCloud могут находиться неофициальные загрузки. Объекты со словами cover/remix/live в названии фильтруются, но это эвристика; перед публичным использованием требуется юридическая и контентная верификация.
8. **Компиляция и фронтенд-тесты:** установка зависимостей через сеть дала `EAI_AGAIN registry.npmjs.org`; поэтому полные `pnpm typecheck`, `pnpm lint`, `pnpm test` и `pnpm build` **не выполнены**. Автоматический GitHub Actions workflow запускает их после загрузки и может выявить дополнительные ошибки.

Зафиксировать фактическую долю найденных MBID, похожих записей и подтверждённых встраиваемых URL от репрезентативной тестовой выборки.

## 4. Публикация GitHub Pages + Render

1. Распаковать полный архив модернизированного NoteSound. **Сделать копию действующего GitHub-репозитория и базы пользователя до замены файлов**. Загрузить весь исходный каталог проекта в свой репозиторий NoteSound (включая скрытую `.github/workflows/deploy.yml`), не загружать `node_modules`, `.env`, `server/.env`, ключи и токены.
2. Выполнить команды проверки из предыдущего раздела. В GitHub Actions существующий workflow `deploy.yml` выполняет `pnpm install --frozen-lockfile`, `typecheck`, `lint`, `test`, `build` и лишь затем Pages. При ошибке workflow оставить предыдущую опубликованную сборку.
3. GitHub → **Settings → Pages → Build and deployment → Source: GitHub Actions**. В `Settings → Secrets and variables → Actions → Variables` настроить `VITE_DISCOVERY_API_URL` равным **HTTPS-корню** собственного Render, например `https://your-service.onrender.com` (без `/api/...`); `VITE_BASE_PATH=/NoteSound/`, если репозиторий и URL прежние. Не помещать SoundCloud OAuth secret в Variables, `VITE_*` или `public/config.js`.
4. Render → **New → Web Service**, подключить репозиторий. Root directory — корень репозитория. Runtime **Node** либо совместимый Dockerfile проекта, build command может быть пустым для чистого Node HTTP API, start command `node server/index.mjs`. Node.js 24 рекомендуется, как в GitHub workflow. Задать `HOST=0.0.0.0`, `PORT` предоставляемый Render, `APP_ORIGINS=https://<имя>.github.io,http://127.0.0.1:5173` с *точными origin*. Для текущего сайта исходника это `https://egeduoru.github.io`. Секреты хранить только в Render Environment.
5. Серверные переменные для новой интеграции: `MUSICBRAINZ_CONTACT=https://github.com/<владелец>/<репозиторий>` (с реальным контактом/URL), `SOUNDCLOUD_CATALOG_APPROVED=false`, `SOUNDCLOUD_CLIENT_ID=` и `SOUNDCLOUD_CLIENT_SECRET=` пустые без полученного разрешения. В случае оформленного и соответствующего условиям разрешения задать `SOUNDCLOUD_CATALOG_APPROVED=true` и полученные серверные credentials; **это не заменяет отдельной проверки прав на музыку**.
6. Render API после запуска: `GET /api/music/metadata?q=MACAN` и `/api/music/similar?q=MACAN%20ASPHALT%208`. Без разрешения `GET /api/discovery/soundcloud/search?q=MACAN` должен вернуть `{enabled:false,tracks:[],warning:...}`. Отдельно запустить `/api/catalog/status` и проверить CORS.
7. После зелёного workflow открыть Pages и Telegram Mini App. В существующем экране «Настройки → Музыкальные источники» включать только реально доступные источники. Для публичного открытия нового каталога нужна полноценная проверка прав и устройств. Сохранить адрес бота и URL, если они не меняются.

**Примечание о запуске локально:** штатный сервер использует порт `3001`. Разработческий Vite config проксирует `/api/discovery` и `/api/music` на `127.0.0.1:3002` (исторический setup проекта). Для обоих процессов используйте существующий `node scripts/start-local.mjs` и проверьте порт запускаемых сервисов; при раздельном запуске согласуйте значения `PORT=3002` и frontend proxy. В GitHub Pages Vite proxy не используется: нужен HTTPS URL Render.

## 5. Поддержка, безопасность, расширение каталога

* Не обходить авторизацию, DRM, запреты встраивания, лимиты или robot protections. Не извлекать временные аудиоссылки из SC iframe; никогда не распространять чужие записи из Wave Mix без доказанного разрешения.
* Для MusicBrainz обеспечить идентифицируемый User-Agent, лимит частоты и согласовать допустимое применение с актуальными правилами. Данные записей не означают право использовать аудио.
* ListenBrainz Labs — экспериментальный источник и может менять алгоритмы/доступность. Не строить публичную гарантию непрерывной Волны на нём одном.
* При дальнейшем расширении добавлять только официальные, разрешённые источники, которые могут возвращать подтверждённые права на проигрывание; реализовать дополнительные резолверы с явной атрибуцией, недублированием и доступностью.
* Для качества рекомендаций получать доступные жанры/теги и пользовательские предпочтения без передачи частных записей на сторонние публичные сервисы. Измерять фактический recall на собственной лицензированной тестовой выборке, не на вымышленных хитах.
